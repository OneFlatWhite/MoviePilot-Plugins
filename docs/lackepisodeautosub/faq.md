# ⑤ 故障排查 FAQ

每条都来自真实事故，附带排查路径。

## 订阅/下载类

### Q1：订阅建了一大堆，但一个都不下载

按顺序查：

1. **「订阅时洗版」是不是开了？**（插件配置页）
   开了会导致所有订阅带洗版标记，MP 搜到资源也报「优先级未达升级条件」不下载。
   处理：关开关 + 清除存量订阅的洗版标记（MP 订阅页批量，或用 `mp_diag_fix.py --fix-wash`）。
2. **MP 后端是不是卡死了？** 网页能开但 API 不响应（curl 订阅接口 60 秒无回包）。
   → 见 Q7 恢复流程。
3. **是不是只在排队？** MP 的订阅周期搜索**每个订阅之间随机休眠 60~300 秒**，
   几百个订阅排一轮要十几个小时。想立刻搜：MP 订阅页点单部搜索，或
   `curl "http://MP:3000/api/v1/subscribe/search/订阅ID?token=API_TOKEN"`（带 ID 时不休眠）。

### Q2：多季缺集的剧只补了第 1 季

MP 会把 `season=None` 的整部订阅**强制归一化为第 1 季**——必须逐季建订阅。
插件一直是逐季订阅；如果你用过第三方批量订阅脚本（season=None），受影响的剧
需要删掉订阅后按季重建。

### Q3：只缺 2 集，MP 却拖回整季 100 多 GB 的大包

两种原因：

1. **Emby 没就绪时触发了搜索**：Emby 重启/未响应期间 MP 查库失败，误判"整季都缺"。
   v1.9.0 起插件触发搜索前会先探 Emby 就绪，根除此类误判；
2. **MP 的"整季包优先"策略**：搜到整季包覆盖缺集时优先选它。
   可通过 MP 订阅规则组限制（或在订阅设置里调整整季包策略）。

### Q4：爱影 API 有资源，转存却失败

看 SA 的回执分类处理（插件日志可见）：

- 「你已经转存过该文件」→ 不是失败！内容已在你 115 里（v1.8.1 起按成功处理）；
- 「分享已取消」→ 死链，自动换下一条或转 PT；
- 「离线失败」→ ed2k 源在 115 网络上不可得，转 PT 兜底；
- SA 无响应 → 跑一遍 `sa_http_test` 检查通道参数。

### Q5：爱影机器人在 TG 里没动静（没有新查询）

爱影查询只在**插件扫描的订阅阶段**产生（每天 4:17 或手动触发）。
如果你手动触发过但没有动静：检查 MP 后端是否健康（Q7）、扫描是否中途超时
（60 分钟保护会提前收尾，剩余的明天继续）。

## 页面/显示类

### Q6：详情页表格有分页器但一行都不显示

v1.9.0 及之前的已知问题（某些 MP 前端版本不渲染 VDataTable 的行）。
**升级 v1.9.1**（三个表已改原生 HTML 渲染）即可。

### Q7：MP 网页能开但什么都不动 / docker restart 卡死

这是 MP 后端或容器僵死（真实发生多次）。**不要用 `docker restart`（会挂住）**，用：

```bash
# Synology SSH 上执行（其他系统换成自己的 dockerd 服务名）
sudo systemctl restart pkg-ContainerManager-dockerd
sleep 30 && /usr/local/bin/docker start moviepilot
```

原理：dockerd 对容器"失联"（进程死了但状态显示 Up），重启 dockerd 让一切重来，
其他容器不受影响（有 restart 策略的会自动拉起）。

**防复发三件套**：
1. 媒体库同步改每天一次（别和下载高峰撞车）；
2. qb 限同时下载数/限速；
3. 频繁复发 → 套件中心升级/修复重装 Container Manager。

### Q8：插件版本莫名其妙变回旧版

MP 启动会按插件市场仓库**同步**已安装插件的文件——如果 GitHub 仓库里是旧版，
本地新版会被覆盖。根治：把新版本**推送到 GitHub 仓库**（同步就变成升级而不是降级）。
本插件 v1.9.1 起仓库与发布版一致。

## 数据/链路类

### Q9：115 里文件越堆越多，Emby 里却没有

卸货区（如 `我的接收`）的文件要刮削归档才进媒体库。查：

1. Symedia 是否**真的有归档任务监控该目录**（真实事故：任务不存在，300G 无人归档）；
2. 归档任务是否配了 `failed_dir`——识别失败的文件会堵队列（真实事故：57G 的 3D ISO 反复重试）；
3. CD2 的上传任务列表/缓存是否正常。

### Q10：死种怎么处理

- 插件每轮检测 qb 里 0 进度超 N 小时的任务并告警（默认 6 小时）；
- 老剧死种不会自己活过来：MP 订阅页找到该剧 → 手动点一次搜索换种；
- 「自动删除死任务」开关慎开（删了 MP 可能仍标记已下载，需手动重搜）。

### Q11：扫描越来越慢

确认「增量扫描」开着（v1.6.0+，默认开）：已完结已补齐的剧记账跳过，
日常一轮几分钟。如果天天都是全量：检查是不是每天都被判成"全量日"（默认仅周日），
或账本被「清空历史」清了。

### Q12：重启 MP 后又要重新登录

MP 默认每次启动重新生成 SECRET_KEY，所有登录态作废。compose 加一行固定：

```yaml
- SECRET_KEY=一段固定的长随机字符串
```

## 日志怎么看

- MP 主日志：MP → 日志，搜「缺集自动补齐」「订阅」；
- 插件独立日志：MP 容器内 `/config/logs/plugins/lackepisodeautosub.log`
  （宿主挂载目录下同名位置）；
- SA（Symedia）日志：看 `#115助手#` 前缀的转存回执；
- 关键词：`爱影 API`、`SA(HTTP)`、`已触发即时搜索`、`入库验证`、`完结账本`。
