## 一、详情页怎么看

MP → 插件 → 缺集自动补齐 → 点击卡片打开详情页。

### 顶部状态条

- **爱影通道**：TG 登录状态 + 通道启用状态
- **上一轮汇总**：扫描 X 部 · 发现缺集 X · 订阅 X · 跳过 X · 失败 X · 耗时 · 扫描模式（增量/全量）· 账本跳过 X 部

### 统计卡（两行）

| 卡片 | 含义 |
|---|---|
| 累计扫描 / 累计发现缺集 / 累计订阅 / 累计跳过 / 累计失败 / 已处理剧目 | 历史总量（缺集卡含重复轮次） |
| 待验证 | 已订阅、还没确认入库的部数（越多越好→逐渐下降=健康） |
| 已核销 | 验证回环确认"真的入库了"的部数（持续上涨=健康） |
| 超时未补齐 | 超 N 天没入库的（告警数） |
| 完结账本 | 增量扫描跳过的"已完结已补齐"部数 |
| 本轮/累计爱影补齐 | 115 通道命中数 |
| 爱影剩余次数 / 爱影 API 剩余次数 | TG 机器人额度 / API 额度（各自独立） |

### 三个表（v1.9.1 起为原生 HTML 表格）

1. **补齐验证**：每部在盯的剧——订阅日期、已等天数、剩余缺集、状态
   （蓝=等待入库，**红=超时未补齐**，按已等天数实时计算，最急的排最上）；
2. **疑似死任务**：qb 里 0 进度超阈值的下载任务（名称/已挂时长/状态）；
3. **最近 50 条历史**：每部剧的处理记录，**带渠道列**——
   🔵PT / 🟢115 / 🟠混合，以及渠道详情（如「订阅 S02/S03（sid=469,470）」
   「4K 1080p S1-S5（751.5G）→ SA(HTTP)已提交」「按缺集选包：缺 5 集，选 S01E06-S01E10，预计覆盖 5/5」）。

> 页面是静态快照，操作后手动刷新。

## 二、通知长什么样

每轮结束发一条汇总（MP 配置的通知渠道）：

```
模式：正式订阅
扫描：增量模式，扫描剧集 X 部，增量跳过 Y 部，发现缺集 Z 部
新增订阅：A 部，跳过：B 部，失败：C 部
爱影通道：115 补齐 N 部
本轮订阅：
· [PT] 有你才幸福（缺 1 集）
· [115·API] 兰森峡谷（缺 2 集）Ransom Canyon S01E01-E02
· [混合] 修复错误！（115补1集+PT补5集）
· …等共 N 部
```

超时告警单独发：「《XX》订阅 7 天未入库，已自动重置订阅重新搜索」。

## 三、远程 API（接企业微信/脚本）

都挂在 `/api/v1/plugin/LackEpisodeAutoSub/` 下，用 MP 的 API_TOKEN 鉴权：

```bash
# 查状态（待验证/已核销/今日已订阅/配额/SA通道/实时进度）
curl "http://MP:3000/api/v1/plugin/LackEpisodeAutoSub/status?apikey=TOKEN"

# 手动触发一轮扫描（同步执行，大库较慢）
curl "http://MP:3000/api/v1/plugin/LackEpisodeAutoSub/scan?apikey=TOKEN"

# 爱影 API 联调（见通道篇）
curl "http://MP:3000/api/v1/plugin/LackEpisodeAutoSub/ay_api_test?tmdb_id=44277&save=0&apikey=TOKEN"

# SA HTTP 联调（见通道篇）
curl "http://MP:3000/api/v1/plugin/LackEpisodeAutoSub/sa_http_test?content=帮助&apikey=TOKEN"
```

## 四、每天的正确姿势

- **早上**：扫一眼汇总通知（新订了几部、爱影命中几部）；
- **详情页待验证**：慢慢下降 = 一切正常；出现红色超时 = 按 [FAQ](faq.md) 处理；
- **爱影 API 剩余次数**：月底归零前注意（6500/月，正常用绰绰有余）；
- **每周日**：全量扫描日，耗时比平日长是正常的。

## 五、性能预期（参考实测）

| 项目 | 预期 |
|---|---|
| 增量扫描（日常） | 几分钟 |
| 全量扫描（每周日/首轮） | ~60 分钟（几千部库） |
| 爱影 API 查询 | ~1 秒/部 |
| SA 转存 | 秒级（115 云端内部复制） |
| PT 下载 | 取决于种子热度，老剧可能死种（死任务检测会告警） |
