# ② 配置项全解

[← 返回首页](README.md)

MP → 插件 → 缺集自动补齐 → 设置图标。按分组逐项说明。

---

## 基础

| 配置项 | 推荐值 | 说明 |
|---|---|---|
| 启用插件 | 调试通过后开 | 关闭则不定时运行，只能手动「立即运行一次」 |
| 立即运行一次 | 需要时开 | 保存后约 3 秒跑一轮，跑完自动关 |
| 调试模式（仅记录不订阅） | **首次必须开** | 开着只扫描记录不真订阅；关了才真干 |
| 汇总通知 | 开 | 每轮结束发汇总（扫描模式/新订/跳过/失败/爱影命中） |
| 扫描频率 | 每天一次 | 不建议更勤，浪费 TMDB 配额 |
| 几点跑 / 几分跑 | 4 点 17 分 | 凌晨低峰对 PT 站友好；建议避开整点/半点 |
| 自定义 cron | 留空 | 高级用户，仅频率选「自定义」时生效 |

## 风控

| 配置项 | 推荐值 | 说明 |
|---|---|---|
| 每日最大订阅数 | 200（勿超 300） | 太大瞬间打爆站点和下载器 |
| 单部剧缺集数上限 | 100 | 防「整部识别错误」误订；柯南类长篇按需调大 |
| 订阅间隔（秒） | 2 | 填 0 容易触发限流 |
| 连续失败熔断次数 | 5 | MP/TMDB 挂了自动停，不白请求 |
| 单轮超时保护（分钟） | 60（大库首轮 120） | 防扫描卡死；超时提前收尾，下轮继续 |

## 验证回环（订完盯着入库）

| 配置项 | 推荐值 | 说明 |
|---|---|---|
| 未入库告警天数 | 7 | 订阅超 N 天没入库就告警；太小会误报慢资源 |
| 超时自动重置订阅 | 开 | 超时后自动重置订阅（清空已下载记录），MP 下轮重搜 |
| 订阅丢失自动补订 | 关 | 订阅被人为删除后自动补订；开了会"复活"你手动退的订 |
| 死任务判定（小时） | 6 | qb 里 0 进度挂 N 小时视为疑似死任务 |
| 补齐时发 ✅ 通知 | 关 | 开了补齐一部发一条，多的时候刷屏 |
| 自动删除死任务 | 关 | 开了自动删（不删文件）；删除后 MP 可能仍标记已下载，需手动点一次搜索 |
| 磁盘告警路径 | `/video/downloads` | MP 容器内下载目录路径 |
| 剩余空间告警阈值（GB） | 200 | 低于此值每轮告警 |

## 增量扫描（v1.6.0+）

| 配置项 | 推荐值 | 说明 |
|---|---|---|
| 增量扫描 | **开** | 「完结账本」机制：TMDB 已完结且无缺集的剧记账后直接跳过，日常一轮从 ~70 分钟缩到几分钟 |
| 每周全量扫描日 | 周日 | 当天忽略账本全库重查，防增量漏网（如完结剧出新季、你删了集） |
| 本轮强制全量扫描 | 关 | 一次性开关，下一轮忽略账本全量，跑完自动关 |

> 永远不漏的三类：在播剧、待验证的剧、不在账本里的剧（含新入库）。
> 发现缺集或订阅失败的剧自动移出账本（自愈）。

## 优先级策略

| 配置项 | 说明 |
|---|---|
| 优先地区（多选） | 命中的剧排前面；依据 TMDB 出品国家/原始语言 |
| 动漫优先 / 纪录片优先 | TMDB 类型命中提前一档 |
| 同层排序规则 | 缺集少的优先（默认，快速见效）/ 缺集多的优先 / 评分高的优先 |

层级规则：每命中一项 +1 层，层高的先订；同层按排序规则。每部剧的层级判定写在 MP 日志（搜「优先级队列」）。

## 过滤

| 配置项 | 推荐值 | 说明 |
|---|---|---|
| 忽略特别篇 S00 | 开 | 特别篇/花絮不补 |
| 未完结剧忽略最新季 | 开 | 在播剧最新季边播边下，不算缺集 |
| **订阅时洗版** | **关！** | 开了 MP 会追更高画质版本。**真实事故：误开导致 241 部订阅全部"优先级未达升级条件"永不下载** |
| 排除关键词 | 按需 | 剧名含任一词就跳过，如 `演唱会,戏曲` |
| 清空历史与已处理清单 | 关 | 谨慎！开了所有剧重新参与订阅，已处理名单/待验证/完结账本全清 |

## 通道类（详见 [③ 通道配置](channels.md)）

| 配置项 | 默认 | 说明 |
|---|---|---|
| 爱影 API 通道 | 开 | HTTP 查 115 资源（主通道） |
| 爱影 API 地址 | `http://api.ayclub.vip:5050/api/user` | — |
| 爱影 API Token | 需自填 | 爱影机器人发 `/token` 获取 |
| 单剧最多提交链接数 | 3 | 精确选包后最多提交几条给 SA |
| tg_id | 留空自动 | 自动从 TG 会话获取；无 TG 才需手填 |
| SA HTTP 直连 | 开 | 转存走 SA 的 HTTP API，不用 TG 机器人 |
| SA 地址/Token/AESKey/CorpID/UserID | 见通道篇 | 企业微信回调参数 |

## 配置备份与恢复

- 插件配置存在 MP 数据库里（`systemconfig` 表 `plugin.LackEpisodeAutoSub`），
  **重装插件/更新版本不丢配置**；
- 「清空历史与已处理清单」是唯一会毁数据的开关，用前三思。
